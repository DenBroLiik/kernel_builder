# Auto Swap 2GiB Smart v2.1.0

Улучшенная версия архива `Auto_Swap_2GiB_Smart_KernelSU_v2.0.zip`.
ID сохранён: `auto_swap_4gb`. Это обновление существующего модуля,
а не второй параллельный модуль и не отменённый swap на 512 МиБ.

## Что исправлено

- Используется `/system/bin/swapon`: BusyBox из KernelSU на проверенном
  телефоне не поддерживает параметр `-p`. Раньше скрипт попадал в запасной
  путь без явно выбранного приоритета.
- Дисковый swap получает приоритет 0 при более высоком приоритете zram.
  Если приоритет zram нулевой или отрицательный, используется автоматический
  отрицательный приоритет ядра. Отрицательные числа в `swapon -p` не передаются.
  После включения скрипт проверяет наличие swap и его приоритет в `/proc/swaps`.
- Вместо каталога с PID применяется `flock`: нет гонки между созданием
  блокировки и записью PID, и блокировка снимается при завершении процесса.
- При переходе с 4 на 2 ГиБ старый неактивный файл сохраняется, пока новый
  не создан, отформатирован и успешно включён. При отказе старый файл
  восстанавливается. Работающий swap не отключается.
- Временный файл создаётся в закрытом каталоге root с правами 0700.
  Неизвестные временные файлы не перезаписываются.
- Для резервного создания через `dd` используется низкий приоритет CPU
  и `conv=fsync`. Если `fallocate` не подходит файловой системе, выполняется
  повторная попытка через `dd` с сохранением старого файла.
- При незавершённой загрузке Android скрипт прекращает работу, не создавая
  дополнительный zram раньше штатной настройки памяти.
- При обновлении сохраняются `config.conf` и запись о собственном zram.
  Системный zram и глобальные параметры VM не изменяются.

## Режимы

В `/data/adb/modules/auto_swap_4gb/config.conf`:

- `MODE=auto`: при существующем системном zram — дополнительный swap-файл
  2 ГиБ. Если системного zram нет, попытка создать отдельный zram 2 ГиБ
  с LZ4; при невозможности — файл.
- `MODE=file`: swap-файл 2 ГиБ.
- `MODE=zram`: отдельный новый zram 2 ГиБ без перехода к дисковому файлу.

Существующий Android zram не сбрасывается, его размер и алгоритм не меняются.
2 ГиБ zram — логическая вместимость до сжатия, а не заранее занятые 2 ГиБ RAM.
Дисковый файл занимает 2 ГиБ на накопителе. Приоритет swap определяет выбор
области для выгрузки, но не направляет туда исключительно фоновые приложения.

## Установка

Установить ZIP поверх существующего модуля в KernelSU и перезагрузить телефон,
когда это удобно. Само обновление не отключает активный swap на 4 ГиБ:
переход на 2 ГиБ происходит при загрузке, когда старый файл неактивен.
Кнопка Action показывает состояние и журнал. Фонового опроса после настройки
нет: сервис выполняется один раз и завершает работу.

```
adb shell "su -c 'cat /proc/swaps'"
adb shell "su -c 'cat /data/adb/modules/auto_swap_4gb/swap.log'"
```

Если в закрытом каталоге `/data/local/tmp/.auto_swap_smart` обнаружены остатки
прерванной миграции, модуль может остановиться для проверки вместо удаления
неизвестных файлов. Не удалять ни один файл, используемый в `/proc/swaps`.

## Проверки и границы

Проверены синтаксис и выполнение настоящего service.sh в имитированной среде:
блокировка второго запуска, приоритеты zram 32758/0/-2, повторный запуск,
сохранение активного swap, успешная миграция, восстановление старого файла
после отказа swapon, ошибки выделения/форматирования, нехватка места,
неизвестные файлы, создание и очистка нового zram, незавершённая загрузка.

Инструменты swap/sysfs в тестах подменены: реальная установка и проверка
после перезагрузки ещё не выполнены. Улучшение скорости или автономности не
измерено. Удаление модуля не вызывает swapoff и не стирает активные данные;
после перезагрузки файл остаётся, но больше не подключается этим модулем.
