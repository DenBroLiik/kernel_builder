# Внешние USB-устройства для stone

Настройки находятся в [stone_defconfig](kernel/arch/arm64/configs/stone_defconfig).
Это конфигурация семейства stone, а не универсальное ядро для других телефонов.
Включённые драйверы встроены в образ (`=y`): текущий AnyKernel не устанавливает
отдельные модули, а исходная конфигурация отключает CONFIG_MODULES.

## Добавленная поддержка

| Устройства | Драйверы / семейства |
| --- | --- |
| Wi-Fi AC600 RTL8811CU | Встроенный vendor-драйвер 8821cu; также RTL8821CU. [Источник и локальные изменения](kernel/drivers/net/wireless/realtek/rtl8821cu/INTEGRATION.md) |
| Другие USB Wi-Fi | ath9k_htc, carl9170, ar5523; MT7601U, MT7610U, MT7612U; rt2500usb, rt73usb, rt2800usb; rtl8187 и rtl8xxxu |
| USB Bluetooth | btusb с Intel, Broadcom, Realtek, MediaTek; ath3k. Реальная совместимость зависит от USB ID и версии чипа |
| Bluetooth-протоколы Linux | RFCOMM/TTY, BNEP/PAN, HIDP |
| USB Ethernet | ASIX, Realtek RTL8150/8152, Aquantia, SMSC, DM9601, SR9700/9800, MCS7830, CH9200, CDC Ethernet/NCM, RNDIS |
| USB-модемы | CDC MBIM, Huawei NCM, QMI WWAN, Option, Qualcomm, Sierra; требуется программа управления модемом |
| USB UART и платы | CH340/CH341, CP210x, FTDI, PL2303, CDC ACM |
| Принтеры | USB printer class; требуется совместимое приложение/служба печати |
| Xbox-контроллеры | Добавлены вибрация и светодиоды к уже включённому xpad |
| Сетевые диски | SMB3, NFSv3/v4/v4.1/v4.2; SMB1/SMB2.0 и слабые пароли отключены |
| Образы Linux | SquashFS с Zlib/LZ4/XZ/Zstd |
| Root-контейнеры | PID/IPC namespaces, SysV IPC, POSIX queues, cgroups pids/devices; без MEMCG и user namespaces |

Включены стандартные защиты ARM64 KPTI, branch predictor/history mitigations,
SSBD и защита EL2-векторов. Их фактическая применимость зависит от CPU и firmware.
USB EHSET/link-layer/dummy-тестовые драйверы и эмуляция температуры отключены.
Штатные термодатчики, термозащита, SELinux и проверка целостности сохранены.

Поддержка USB storage/UAS, FAT/exFAT, USB-аудио, UVC-камер, USB HID и ряда
геймпадов уже присутствовала. Подключение камеры не гарантирует её появления
в штатном приложении камеры.

## RTL8811CU и Android

В исходном ядре 5.4.304 драйвера RTL8811CU не было. Добавлен отдельный
[rtl8821cu](kernel/drivers/net/wireless/realtek/rtl8821cu/), подключённый к Kbuild
и Kconfig. Это не драйвер RTL8192CU и не rtl8xxxu.
Идентификаторы устройств перечислены в
[supported-device-IDs](kernel/drivers/net/wireless/realtek/rtl8821cu/supported-device-IDs).
Если адаптер определяется как установочный CD-ROM (например, USB ID
0bda:1a2b), может понадобиться usb_modeswitch в пользовательской среде:
Wi-Fi-драйвер привязывается к устройству после переключения режима.

У RTL8811CU firmware включена в исходники драйвера. Другим Wi-Fi и Bluetooth
адаптерам могут понадобиться отдельные firmware-файлы. Имя отсутствующего
файла следует брать из dmesg; путь загрузки определяется прошивкой Android
и firmware loader. Для cfg80211 также нужна подходящая regulatory.db с подписью.

Появление сетевого интерфейса в Linux не означает, что Android Wi-Fi HAL
автоматически начнёт использовать внешний адаптер. Для подключения могут
понадобиться root, iw, wpa_supplicant и настройка маршрутизации либо доработка
HAL/прошивки. Аналогично, штатный Bluetooth Android не обязан работать через
внешний USB HCI: может потребоваться отдельная настройка Bluetooth HAL или
совместимая Linux-среда со своим стеком. Поддержка конкретного нового BT-чипа
не появляется только от включения btusb.

Для питания внешних устройств нужен рабочий USB host/OTG. При недостатке
питания используйте хаб с внешним питанием. Конфигурация не добавляет телефону
USB 3.0, видеовыход или возможности, которых нет в аппаратуре.

## Проверка на телефоне

После сборки и загрузки подходящего для телефона образа выполните с компьютера
(нужны ADB и root на телефоне):

```sh
adb shell su -c 'dmesg | tail -n 150'
adb shell su -c 'ip link show'
adb shell su -c 'ls /sys/class/bluetooth'
adb shell su -c 'ls /sys/class/tty'
```

При наличии iw в Android/Linux-среде:

```sh
iw dev
iw phy
```

Проверить: USB ID адаптера, привязку драйвера, отсутствие ошибок firmware,
сканирование, соединение и передачу данных в нужных диапазонах, отключение
и повторное подключение, сон/пробуждение, работу встроенного Wi-Fi/Bluetooth
и зарядки. Для Bluetooth проверить создание hci-интерфейса и реальное
сопряжение через настроенный стек. До этих проверок аппаратная работа
считается неподтверждённой. Перед прошивкой сохраните рабочий boot-образ
и возможность восстановления.

## Русское меню сборки

На компьютере:

```sh
bash build.sh
```

В интерактивном терминале откроется меню: сборка с ZIP, только проверка
конфигурации, упаковка готовой сборки, резервная копия POCO и описание функций.
Можно выбрать KernelSU и пять групп возможностей. Исходный defconfig при этом
не меняется; выбор сохраняется в FEATURES.env внутри каталога результата.
Безопасные базовые настройки и термозащита не являются переключателями меню.
Диагностика компилятора/make остаётся на языке этих инструментов.

Пример без интерактивного ввода:

```sh
COMPILER_PATH="$PWD/validation/clang-r563880c/bin" \
  FEATURE_USB_WIFI=1 FEATURE_USB_BLUETOOTH=1 FEATURE_NETFS=1 \
  FEATURE_CONTAINERS=1 FEATURE_USB_GADGET=1 KSU_MODE=keep \
  bash build.sh --build
```

`--config` выполняет только конфигурацию и проверки. `--package` принимает
каталог успешной сборки. Упаковка проверяет хеши и идентификатор исходников;
при ошибке сборки либо изменении исходников старый результат не упаковывается.

## Использование утилит на POCO

Утилиты запускаются вручную на POCO с новым ядром, обычно из локального
root-терминала. Сначала скопируйте нужные файлы из tools/ в /data/local/tmp
именно POCO. Подключённый Redmi 7A не подходит; скрипты отказываются работать
с pine. Скрипты не отключают SELinux и не прошивают разделы.

### Состояние и диагностика

```sh
# На телефоне; отчёт сохраняется только локально.
su -c 'sh /data/local/tmp/phone-report.sh' > /sdcard/stone-report.txt
```

Отчёт может содержать журналы работы и сетевые идентификаторы. Просмотрите его
перед публикацией. Для оценки сна сделайте снимок до и после нескольких часов
простоя; сравнивать нужно при одинаковых настройках сети и нагрузки.

### Временные USB-функции

```sh
# На телефоне, из локального root-терминала:
sh /data/local/tmp/phone-usb.sh status
sh /data/local/tmp/phone-usb.sh enable keyboard
# Либо: enable mouse; enable midi; enable iso /sdcard/example.iso
sh /data/local/tmp/phone-usb.sh commit
# Вернуть исходный USB-режим:
sh /data/local/tmp/phone-usb.sh restore
```

Включение кратковременно переподключает USB. Скрипт сохраняет существующие
функции, включая ADB, и добавляет одну свою функцию. Без commit за 60 секунд
срабатывает откат. При ошибке выполняется восстановление. ISO экспортируется
только для чтения; блочные устройства не принимаются. Не изменяйте файл ISO
во время экспорта. HID-события и MIDI передаёт отдельное совместимое приложение;
скрипт создаёт интерфейс, а не экранную клавиатуру.

USB HAL может переписать конфигурацию; при нескольких активных конфигурациях
утилита откажется от изменения. Это не проверенная на POCO интеграция с HAL.
Если восстановление не удалось, перезагрузка возвращает штатную инициализацию
USB Android. Commit не создаёт автозапуска и не делает изменение постоянным.

### Питание и память

```sh
# На телефоне с root:
sh /data/local/tmp/phone-power.sh status
sh /data/local/tmp/phone-power.sh battery
sh /data/local/tmp/phone-power.sh balanced
sh /data/local/tmp/phone-power.sh restore
```

Используется штатная служба энергосбережения Android; сохраняется исходный
режим. Частоты CPU/GPU, напряжения, термолимиты, зарядные токи, размер zram
и swappiness не подменяются произвольными значениями. Профиль «разгон» не
добавлен. Подбор памяти и автономности требует замеров именно POCO.

### Сетевые диски

```sh
# На телефоне, в root-среде с mount.cifs/mount.nfs:
sh /data/local/tmp/phone-netfs.sh smb //192.168.1.10/share nas /data/local/tmp/smb.credentials
sh /data/local/tmp/phone-netfs.sh nfs 192.168.1.10:/export nas
sh /data/local/tmp/phone-netfs.sh unmount nas
```

Выберите SMB или NFS: имя точки `nas` не должно быть занято. SMB credentials
содержит строки username=... и password=..., принадлежит root и имеет права
600 или 400. Пароль не передаётся аргументом командной строки. Монтирование
только для чтения, с nosuid/nodev/noexec; SMB требует SMB3 с шифрованием.
Видимость для приложений зависит от SELinux и пространства монтирования.

### Linux-контейнеры

Добавлены механизмы изоляции процессов/IPC и ограничения числа процессов,
устройств и уже существующего CPU-контроллера. Сам runtime и rootfs нужны
отдельно. Rootless-контейнеры и ограничения RAM не обещаются: USER_NS/MEMCG
выключены. В существующей реализации MEMCG есть обращения к удалённому
shrinker_rwsem; ради контейнеров общий механизм reclaim не переписывался.
ANDROID_SIMPLE_LMK явно выключен: при уже включённом PSI он и раньше
отбрасывался зависимостями Kconfig. Механизм управления памятью не заменялся.

## Проверки и ограничения релиза

Полная сборка Image, DTB и DTBO с Clang 23.1.3 / ThinLTO завершилась успешно
в validation/stone-final. Восстановлена совместимость SquashFS с новым API
Zstd этого дерева и устранены конфликты символов ath9k_htc/Qualcomm и vendor AES.
Обнаруженные предупреждения нового 8821cu об использовании неинициализированных
переменных исправлены. В унаследованном коде ядра остаются другие предупреждения.

Тесты tests/test-tools.sh проверяют отказ на другом телефоне, защитные проверки
конфига, русское меню, строгий разбор профилей, сохранение регистра Kconfig,
а также добавление USB-функций/откат/commit и питание на имитации интерфейсов.
Они не являются аппаратным тестом и не доказывают работу Android HAL.

Android Clang r563880c скачан из зеркала релиза
https://github.com/SA9990/Toolchain/releases/tag/clang-r563880c . SHA256 архива:
`57b456636aa9c3f5e159bc1dd6eddd7c6de654281cad84376e408a5d35f91bab`.
Результат окончательной сборки этим компилятором отражается в BUILD-INFO.txt
и BUILD-OK соответствующего каталога; наличие скачанного компилятора само по
себе не означает успешную сборку.

В этой сессии полная сборка Android Clang 21.0.0 (r563880c) с ThinLTO
завершилась успешно в validation/stone-android21; итоговая конфигурация и
контрольные суммы проверены. Собран пакет
`artifacts/Eclipse-Multifunction-EXPERIMENTAL-stone-20261024T123234Z.zip`
с KernelSU и всеми пятью группами возможностей. ZIP прошёл unzip -t.
Установщик сохраняет исходную проверку семейства устройства и ограничение
версий Android 15–17. Это не подтверждение загрузки с конкретной прошивкой.

### Исправление KernelSU после первого запуска

Пользователь установил пакет 20261024T123234Z и сообщил об успешном запуске
рабочего стола. Через ADB подтверждены POCO X5 5G / moonstone, Android 17,
ядро 5.4.304-Eclipse. Это подтверждает загрузку первой сборки, но не тест
автономности, сна и всей периферии.

В первой сборке root не работал: CONFIG_KSU=y, но оба механизма хуков были
выключены, а ручные хуки в основном дереве отсутствуют. Первоначальный
build.sh отдельно включал CONFIG_KSU_HACK_ARM64_BRANCH_LINK после defconfig;
при переделке сборщика этот шаг был упущен. Теперь параметр явно задан в
stone_defconfig. Проверка конфигурации отклоняет KernelSU без механизма хуков
и без LSM-интеграции; добавлен регрессионный тест и проверка режима без KSU.

Менеджер на телефоне: me.weishu.kernelsu, v3.3.1-21 / versionCode 32701.
Сертификат APK имеет размер 0x363 и SHA256
4359c171f32543394cbc23ef908c4bb94cad7c8087002ba164c8230948c21549 — этот ключ
явно разрешён в текущем manager/apk_sign.c. Приложение не переустанавливалось.

Исправленный пакет:
`artifacts/Eclipse-Multifunction-EXPERIMENTAL-KSU-stone-20261024T124858Z.zip`.
Он собран Android Clang 21 / ThinLTO и прошёл проверки конфигурации, SHA256 и ZIP.
После повторной установки пользователь подтвердил наличие root. По ADB
подтверждены ядро #2 и включённый CONFIG_KSU_HACK_ARM64_BRANCH_LINK. ADB shell
пока не получает su; разрешения shell не включаются автоматически. Старый пакет оставлен на компьютере
как предыдущий загружающийся вариант; его root не работает.

По /proc/config.gz на работающем POCO подтверждены RTL8821CU, btusb,
RTL8152, QMI WWAN, USB serial/ACM/audio/UVC, HID/MIDI/mass-storage gadget,
CIFS/NFS/SquashFS, PID/IPC namespaces и WireGuard. Утилиты phone-usb.sh,
phone-netfs.sh, phone-power.sh и phone-report.sh скопированы в /data/local/tmp,
их SHA256 на телефоне совпали с локальными файлами. Termux установлен.
Штатный режим энергосбережения прочитан как 0; он не изменялся.
Внешние USB-адаптеры не обнаружены в доступном shell списке; наличие драйверов
не является проверкой подключённого оборудования. Переключения USB не выполнялись.

Восстановление, сон, батарея, встроенное радио, камеры и внешняя периферия
по-прежнему требуют проверки. Статус — EXPERIMENTAL. Подключённый ранее
Redmi не использовался для прошивки или тестирования этого ядра.

Логи оставлены в validation/ и исключены из Git, пакеты — в artifacts/.
Дерево kernel/ является отдельным Git-репозиторием: для переноса результата
нужны изменения обоих репозиториев, включая новый каталог драйвера.
